### R01 — Retired-generation edits still reach host state

[`applyLeanWorkspaceEdit`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/src/workspaceEdit.ts#L239) awaits document loads and then dispatches updates without checking that the originating connection is still current. A probe started a cross-file edit with a suspended loader, disconnected the session, and then completed the load. The operation returned `applied: true` and the host's `onDocumentChange` received `OLD-GENERATION` while the session was idle.

This can let an old rename or infoview edit alter host-managed text after a reconnect. Disconnecting a transport does not cancel an operation that has already advanced into asynchronous host work.

**Repair:** carry an operation-lifetime signal or generation check from the originating request through awaited loads and validate it before mutation. Preserve intentional offline workspace editing; a blanket rejection of all disconnected workspaces would change that separate use case. Add a regression that resolves the old loader only after a new generation has become active and verifies that neither host text nor the new view changes.

### R02 — One malformed child frame can kill the backend

[`forwardLspFrames`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/demo/server/lspProcessBridge.mjs#L23) throws inside a stream `data` callback when a header lacks `Content-Length`. There is no session-level error containment around that callback. Feeding `not-an-lsp-header\r\n\r\n` to the actual parser in an isolated Node subprocess exited with status 1 and an uncaught `Malformed LSP header` stack trace.

**Repair:** report a framing error to the owning connection, settle/close that session and reap its child, while leaving the HTTP server and other sessions alive. Test this at the actual process-relay boundary, not only by asserting a parser exception.

### R03 — Repeated navigation selects an invisible editor

[`LeanWorkspace.displayFile`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/src/workspace.ts#L541) returns an existing view before calling the host's display callback. In the new [workspace example](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/examples/workspace/publicLeanWorkspace.ts#L117), the callback is responsible for choosing the active URI and showing its panel.

Visit Helper through F12, return to Main, then navigate to Helper again. The retained Helper view is returned, but Main stays active and Helper stays hidden. A jsdom probe with real CodeMirror views reproduced this; infoview document navigation uses the same workspace path. The browser test covers only the first visit.

**Repair:** distinguish obtaining a retained view from activating a document. A display request must reach host activation even when the view already exists, with an existing-view fallback when no host activation is supplied. Add repeated Main → Helper → Main → Helper navigation and infoview navigation to the real and packed browser scenarios.

### R04 — Late loading rewinds the version counter

[`loadFile`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/src/workspace.ts#L275) resumes after the host loader and calls `trackVersion` before `addFile` checks for an already-created file. If a view opens and its document advances while the load is pending, the late load resets the counter even though its newly constructed file is discarded. The next closed-file update in the probe moved the existing file from version 2 to version 1.

**Repair:** recheck current document identity after the await and avoid installing stale loader metadata over a newer file. Define how explicit loaded versions interact with reopening and the per-URI monotonic counter. Test a pending load racing with open/edit/close and subsequent updates.

### R05 — A retired client can accept a request that never reaches a timeout

The pinned upstream client implementation (`@codemirror/lsp-client@6.3.0`, installed `dist/index.js:599–604,704–716`) retains its transport reference and replaces `initializing` with a new unresolved promise. Requests wait for that promise before creating their timeout. [`LeanEditorSession`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/src/session.ts#L255) retires each client but exposes it through connection handles without an additional request-lifetime boundary.

After disconnect, the probe observed `client.connected === true`; a new request remained pending after 30 ms even with a configured 5 ms timeout. The source establishes why the timer has not started. A stale closure can therefore leave work pending indefinitely rather than failing as retired work.

**Repair:** make session retirement observable to request callers and reject work on a retired session client promptly. Settle or cancel pending operations explicitly; do not infer retirement from the upstream `connected` flag. Check both existing in-flight calls and requests first made after retirement.

### R06 — Session callbacks can interrupt lifecycle invariants

[`setState`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/src/session.ts#L271) stops notifying listeners on the first thrown exception. Although disconnect catches the exception and continues some cleanup, later session-aware editor bindings never see the detach state. The probe left a later listener uncalled after an earlier UI observer threw.

Separately, [`connect`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/src/session.ts#L165) publishes `initializing` before connecting the transport. An `onStateChange` callback that disposes the session at that point does not stop the following `client.connect`; the probe recorded `initialize` and `initialized` messages after the session was already disposed.

**Repair:** complete required listener notification/cleanup despite individual observer failures, define how those failures are reported, and recheck ownership after callbacks that can reenter the session. Test throwing observers and dispose/disconnect/reconnect from lifecycle callbacks.

### R07 — Embedded Lean generation has two conflicting definitions

The browser [`leanRole`/renderer](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/demo/src/embeddedLean.ts#L47) recognizes `imports` as a prelude label; the backend [role classifier](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/demo/server/embeddedLeanDocument.mjs#L29) does not. Conversely, the backend accepts `editor-prelude, test` as prelude while the browser does not. Their title normalization also differs.

The same source with a check block followed by one of those import blocks produced different block order. One side placed `import Helper` after `#check Nat`. This is a real difference between the generated text the browser maps and the text the backend initially writes, with possible Lean parse/import and diagnostic-position consequences.

**Repair:** use one pure renderer in `demo/shared` that returns exact generated text and mapping metadata. Test byte-for-byte parity across labels, commas, whitespace, CRLF, Unicode, and preamble/postamble. This is local demo deduplication, not a reason to move Verso worker semantics into editor-platform.

### R08 — Per-message limits do not bound stream memory

The relay [writes to child stdin](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/demo/server/lspProcessBridge.mjs#L181) without respecting the writable high-water mark or `drain`. Twelve allowed-size 900,000-byte messages queued 10,800,312 bytes against a 16,384-byte high-water mark in the probe.

The stdout parser also has no maximum header length, safe bounded declared length, or accumulated-byte cap. An incomplete frame retained 8,388,637 bytes without forwarding a message. Incoming WebSocket `maxPayload` and the process-count limit do not cover these aggregate queues. The reverse direction also has no explicit WebSocket send-queue policy.

**Repair:** bound framing and queued bytes, implement backpressure and cancellation-aware shutdown, and choose a session failure policy for peers that exceed limits. Keep this implementation host-local initially. Tests should drive slow readers, split/malformed headers, incomplete and oversized frames, child exit during writes, and shutdown with queued data.

### R09 — The save check is not an atomic external-writer compare-and-swap

[`save`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/demo/server/leanDocuments.mjs#L50) checks the current hash, writes a temporary file, then unconditionally renames over the destination. Its per-URI queue coordinates only calls through that store instance. An outside writer can modify the destination between the hash check and rename.

A probe watched creation of the temporary file during a 900,000-byte save, wrote `external edit` to the destination, then let the save finish. The store returned success and the outside edit was overwritten. This input fits the default HTTP request limit. The current tests cover an edit before the save check, not one during it.

**Repair/contract decision:** state which writers are coordinated and what protection is promised against external editors or multiple backend instances. Strong guarantees need writer cooperation or a recoverable persistence design; a second hash check merely narrows the race and must not be presented as atomic compare-and-swap. Add the in-flight race test and preserve recovery material if the product promises that concurrent external work cannot be lost.

### R10–R12 — Narrower persistence and shared-adapter edge cases

- **R10:** [temp-file creation mode](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/demo/server/leanDocuments.mjs#L58) is filtered through the process umask. A 0644 source file became 0600 under umask 0077 after saving. Preserve intended permissions explicitly or document the replacement policy.
- **R11:** [`vscodeUriToString`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/packages/editor-platform-vscode/src/customEditorHost.ts#L202) uses `toString(true)`. The [official URI implementation](https://github.com/microsoft/vscode-uri/blob/main/src/uri.ts) minimally escapes `#` and `?`, but leaves literal percent escapes unchanged. Paths containing literal `%23` can alias the serialization of paths containing `#`. Use canonical encoded transport identities and test round trips. This finding is source-verified; no live VS Code host was exercised. The broader hypothesis that `#`/`?` themselves are emitted raw was checked and rejected.
- **R12:** [`appendLog`](https://github.com/ejgallego/lean-mirror/blob/62941d41fc51e75da31556ef5de655d277afc6a4/packages/editor-platform/src/shell/platformStore.ts#L123) uses `slice(-maxEntries)`. For zero, that is `slice(0)` and keeps everything. The probe appended three logs with `maxEntries: 0` and retained all three. Define zero/invalid-limit behavior and test the exposed runtime option as well as the store.

## Architectural assessment

The public core/optional infoview split is useful and remains intact. Hosts owning processes, reconnection policy, filesystem writes, and editor activation is the right boundary. CodeMirror view bindings, workspace mappings and client generations belong in the toolkit. The narrow pinned-upstream registry adapter has explicit late-loaded-file tests; changing it merely to avoid an internal API would not by itself improve correctness.

The shared platform remains a small shell/state/telemetry package, not an analysis engine. Keep Verso's worker snapshots, semantic completeness, source-to-scratch provenance, latest-snapshot policy, and ProseMirror reconciliation local. No new shared provenance framework or browser/Node transport package is justified by this review alone. Coordinate R11/R12 or any later shared semantic change before modifying the directly consumed source package.

The most useful simplification is removing duplicate embedded-source generation. The most useful lifecycle change is an explicit, testable operation-lifetime boundary. These address observed failures rather than requiring a rewrite of the editor or demo.

## Proposed repair slices and acceptance criteria

1. **Lifecycle correctness and the pending multi-file workflow:** fix R01/R03/R04/R05/R06 with focused regressions. Acceptance: late old-generation work cannot mutate current host state; every required detach observer runs; reentrant disposal sends no initialization traffic; retired calls settle; document versions never regress; repeated F12 and infoview navigation activate the retained view. Revalidate core, real-server/consumer paths, workspace and packed-browser scenarios after these changes.
2. **Backend isolation and bounds:** fix R02/R08 locally, using controlled subprocess tests. Acceptance: one malformed or slow child cannot crash the HTTP server or grow queues indefinitely, and closing a session settles and reaps its work. Keep Node implementation details out of the shared browser package.
3. **Persistence contract before landing PR #6:** resolve R09 explicitly and fix R10. Acceptance: tests distinguish stale-before-save from external-write-during-save, document the writer/recovery model, and verify permissions. Add HTTP-level tests for save success, conflict/forbidden/invalid payload status mapping; current tests mainly cover the store and visible UI behavior.
4. **Canonical embedded-source generation:** fix R07 with one local shared implementation and exact output/mapping parity tests. Revalidate embedded Rust/Lean flows. Run the separate external Anneal gate when its generation path is changed; ordinary CI does not establish that integration.
5. **Small shared-package cleanup:** coordinate and fix R11/R12 with contract tests. Run the platform/adapter checks here and arrange real Verso consumer checks with its active agent. Do not run sibling build/test commands opportunistically while its worker branch is changing.

Use small topic-branch commits and preserve the existing caches/toolchains. Do not land PR #6 merely because its present CI is green. Conversely, do not turn unrelated optional integration work into an indefinite prerequisite: each repair slice should exercise the actual failure it fixes.

## Assumptions and remaining coverage

- Host `onDocumentChange` failures are logged and do not prevent cache unloading. A probe demonstrated that behavior, but the hook is not specified as a persistence transaction; treating it as guaranteed data loss would overstate the API contract. Define error/dirty ownership if hosts want persistence guarantees there.
- A socket closing after opening but before LSP initialization may wait for the request timeout before retry. This is source-derived and was not exercised as a separate live early-close browser case.
- Anneal cache identity may need compiler-environment inputs such as `RUSTFLAGS`, but no output-changing collision was established. This is an investigation item, not a confirmed defect.
- This was a full static repository review plus current integration verification and focused adversarial probes, not a proof that all possible execution paths are correct. No sustained multi-hour browser or whole-demo memory measurement was performed.
